# A Few Words of Introduction

This project aims to offer modernized modding tools for the game Aliens vs Predator (1999/Classic). It is being developed as a full-fledged extension for the Blender editor and is, as much as possible, independent – most operations that could be done on the game using the official modding tools should now be possible to perform with this extension.

The extension is generated by an AI agent under my watchful eye. This is not one-shotted slop – every development stage is moderated by me, and changes are manually tested. The project itself is complex enough that during the work, the agent repeatedly hit a wall and without my guidance would not have been able to move it forward. Suffice it to say, bringing the project to a usable state for the first release took a month and cost almost 5 million tokens (around $25).

Nevertheless – some errors will certainly occur, and if you encounter them (or have suggestions for improvements), you can post them on git issues. I'll see what can be done :)

## Requirements

The original version of the extension was developed on Blender 5.2, but it should work on any version of the editor starting from version 4.4.
Additionally (of course), the game itself is needed, as the extension reaches into its resources. BlendAvP was tested with the "classic" Steam version, but other editions of the game should also work.

Optionally: it's worth having a **shape_rifs** folder in the game installation folder from the official modding tools package, which will allow the extension to import models used in the game into the Blender scene. This is not required, but it greatly facilitates work. Otherwise, all level objects will have to be modeled manually. More on this in the "configuration" section.

## Installation

Installation is dead simple and no different from other Blender extensions. After saving the .zip archive to disk (in any folder), simply open Blender and go to its settings via: "Edit => Preferences...".
In the newly opened window, go to the "Get Extensions..." tab and expand the "arrow" next to the "Repositories" field. From the expanded menu, select: "Install from Disc...", point to the downloaded zip... and voila – that's all :)
If the installation was successful, under the "Add" menu (in object mode) you should see a whole new item named simply "AvP", and under the "Export" menu the .rif format should be visible.

## Configuration

After installation, the **Aliens vs Predator RIF Exporter** extension will appear in the extensions list. However, to fully use it, a few additional steps are needed.
In the extension entry, expand the "Details" list:

![[docs\view_details.png]]

This will show the options needed for configuration:

![[docs/ext_settings.png]]

The most important step is to indicate the game installation in the **"Game Directory"** field. It is according to this path that the extension searches for resources necessary to build game levels.

After doing this, click **"Load Game Textures"**, which will load all game textures into the .blend file. You will probably want to use them when constructing your game level :)

**Note: Running this process may cause Blender to become unresponsive – there are a lot of textures and materials and the process can be slow – you need to arm yourself with patience and simply wait. I highly recommend saving such a prepared .blend for the future.**
### Unpack Directory

Before loading textures, Blender must unpack the archives and convert textures from .rim format to a format supported by Blender – .png. **Unpack Directory** indicates this location. In most cases, the default setting (**FFL Dir** – a subfolder in the directory with archives) is fine, but you can change it to your liking to:

* **Game Dir** – the main game folder – useful in situations where you'd want to do something more with the textures. **Note: if your installation already contains modded files, this option will overwrite them**.
* **Custom Dir** – manually indicates the location

### Build Texture Gallery

The button will generate an additional scene in the .blend project file. It serves for inspecting imported materials and as a gallery for faster orientation among the pulled-in resources. It is not required for work, but it's useful to have ;-)

![[docs/mat_gallery.jpg]]

### Clear Texture Library

If there's a need to get rid of previously loaded resources from the .blend file, you can use this button to remove them.

### Load Shapes

This button will only work if the **"shape_rifs"** folder is present in the indicated game directory. Default game installations do not have it.

**The archive with shapes can be obtained from the original "Fox Editing Tools".** After unpacking, this folder is a working archive of all decorative models used in the game. Having it significantly facilitates work on your own content.
After downloading Fox Modding Tools, unpack the **"shape_rifs.zip"** archive to the main game folder – e.g.: **"#:\Steam\steamapps\common\Aliens versus Predator Classic\shape_rifs"**.

If the folder is already available, pressing **Load Shapes** will create a new scene in the open .blend file in which all game models used inside the original levels will appear.

![[docs/shapes.png]]

**Fox Editing Tools** itself must be found and downloaded from the Internet yourself. The extension does not include it and will not include it for licensing reasons.

## Quick Start

Below is a quick recipe for a basic custom level:

1. Model a room from a box with inverted faces or add a basic module from the menu: **Add => AvP => Modules => Room**

![[docs/room.png]]

2. Scale it so that it has a reasonable size (in the example 10x8x4m), assign it materials from the previously imported library, and generate UV mapping as you see fit (in the example below the walls have a cliff texture, and the room uses Cube Projection):

![[docs/basic_module.png]]

3. Add a spawn point from the menu: **Add => AvP => Multiplayer Spawn**

![[docs/spawnpoint.png]]

4. To complete things, it's also useful to have **"Global Generator Data"** from the menu: **AvP => Gameplay**. In the example export we don't add bots, but if you'd like to have them, you must have one global generator and more than one linked module.

![[docs/globalgenerator.png]]

5. A level prepared this way should already export, but for something to be visible in it, it's worth adding a point light and setting ambient:

![[docs/pointlight.png]]

![[docs/ambient.png]]

Both ambient (world tab) and point light are typical Blender objects and do not require special treatment.
**However, it's worth setting them brighter than what comes out of the Eevee preview. The discrepancy in light interpretation between Eevee and the game is still something that requires work and something I struggle with.**

6. Before exporting, it's worth running validation and seeing what it tells us about the current scene: **Add => AvP => Validate**. The script is not perfect, but it should catch the most common errors.

![[docs/validate.jpg]]

7. Finally, all that remains is export: **File => Export => Aliens vs Predator RIF**. The file should be saved to the **avp_rifs\custom** folder – without this it will not appear in the game's map selection list.

![[docs/avp_export.png]]

8. The map should launch both as a skirmish and as multiplayer. Congratulations! You've just become a level designer ;-)

![[docs/ingame_menu.jpg]]

![[docs/ingame.jpg]]

### A Few Important Rules:

* Every room in AvP must be a module, i.e.:
	* The "room" geometry is an object of type "Module" (it is created as this type by default, but you can change it in the objects tab – more about this in the full manual).
	* Modules must be textured – without them they will not render in the game.
		* Materials assigned in Blender are only exported as paths to textures located in .FFL archives. The key here is the material name – **they must not be modified!**
		* **Custom textures are not supported by the RIF Exporter (but maybe they will be in the future)**
		* Shader modification itself has no significance for the exporter, as they are used only for preview purposes for Blender and are not used by the game.
	* Module boxes cannot overlap and intersect. The game engine is very temperamental when it comes to handling their errors. If this condition is not met, attempting to load the level will result in a crash. This is not a problem with the exporter, but with the game itself.
		* Modules can, however, touch each other.
	* Modules are used in the game to generate collision, navigation, and culling calculations (more about this also in the manual), so they are not optional!
	* If the level has more than one module, they must be linked for proper operation (this can be done automatically during export by constructing a hierarchy in the Outliner or by adding entries to the list in the Object tab)
